# 要件定義書 v2: P002 検索結果画面

> DB設計を踏まえた要件定義書の更新

## 目的

キーワード検索またはカテゴリ選択の結果を一覧表示し、入居者が目的のFAQを素早く特定してP003へ進めるようにする。検索結果が0件の場合はP004へスムーズに誘導する。

## 機能

| # | 機能 | 説明 | v1からの変更点 |
|---|------|------|--------------|
| 1 | 検索結果一覧表示 | キーワードまたはカテゴリに合致するFAQをリスト形式で表示する | DB関連テーブル: `faqs`（FULLTEXT検索またはカテゴリフィルタ、READ）、`faq_categories`（JOIN: カテゴリ名取得） |
| 2 | 検索キーワード再入力 | 検索バーを上部に固定し、キーワードを修正して再検索できる | DB関連テーブル: `faqs`（再検索、READ）、`faq_categories`（JOIN） |
| 3 | FAQ詳細への遷移 | 結果リストの各カードタップでP003へ遷移する | DB関連テーブル: なし（ルーティングのみ） |
| 4 | 0件時のAIチャット誘導 | 検索結果が0件の場合に誘導バナーとAIチャットボタンを表示する | DB関連テーブル: なし（取得結果件数の判定はアプリケーション層） |

## Input / Process / Output

| 機能 | Input | Process | Output | DB関連テーブル |
|------|-------|---------|--------|--------------|
| 検索結果一覧表示 | キーワードまたはカテゴリID（URLクエリパラメータ） | `faqs` テーブルに対し、キーワード時は FULLTEXT（ngram）検索で title・body を全文検索、カテゴリ時は category_id でフィルタ。いずれも is_published=true かつ対象 property_id で絞り込み、関連度順に並び替え | 件数テキスト＋FAQカードリスト（title・category名・body冒頭2行） | `faqs` READ, `faq_categories` JOIN |
| 検索キーワード再入力 | 修正したキーワード（テキスト、最大50文字、空白のみ不可） | バリデーション通過後、同様の FULLTEXT 検索を再実行 | 検索結果リストの更新 | `faqs` READ, `faq_categories` JOIN |
| FAQ詳細への遷移 | FAQ ID（カードタップ） | FAQ IDをURLパラメータとしてP003へルーティング | P003（FAQ詳細画面）への遷移 | なし |
| 0件時のAIチャット誘導 | なし（検索結果0件の状態） | 取得結果件数が0であることを検知 | 誘導バナーと「AIに聞く」ボタンの表示 | なし |

## UI状態遷移

| 要素 | 対応機能 | DB関連テーブル |
|------|---------|--------------|
| 検索結果リスト | 検索結果一覧表示 | `faqs`・`faq_categories`（クエリ実行結果に応じてローディング→結果あり→0件→エラー を切り替え） |
| 検索バー | 検索キーワード再入力 | なし（入力値はクライアント側で保持） |
| 検索ボタン | 検索キーワード再入力 | なし（バリデーション通過後に`faqs`へクエリ） |
| 「AIに聞く」誘導バナー | 0件時のAIチャット誘導 | なし |
| FAQカード | FAQ詳細への遷移 | なし |
